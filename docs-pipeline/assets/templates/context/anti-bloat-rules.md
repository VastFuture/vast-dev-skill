# 防膨胀规则 / Anti-Bloat Rules

> 灵感来源：[neat-freak 尺寸体检](https://github.com/VastFuture/khazix-skills/tree/main/neat-freak)
> 用途：保持 CLAUDE.md/AGENTS.md 精简，防止被历史叙事淹没真正规则

## 核心原则

**超尺寸是最高优先级，大于"补本次会话漏掉的同步"**

**原因**：超尺寸的 CLAUDE.md 让 AI 看不到真正重要的规则（被叙事段挤到 200 行外，进不了 prompt 重点段）

---

## 尺寸限制

| 文件 | Soft limit | Hard limit | 红灯线 |
|------|------------|-----------|--------|
| CLAUDE.md / AGENTS.md | ~300 行 / ~15KB | 500 行 / 25KB | 净涨幅 > 30 行 |
| 单条 memory | ~100 行 | 150 行 | - |
| docs/<single>.md | ~1500 行 | 2000 行 | 需切分 |

---

## 净涨幅红灯

**每次更新 CLAUDE.md/AGENTS.md，净涨幅 > 30 行就是红灯**

### 判断标准

新增的是"AI 必须看到的规则"还是"便条"？

| 类型 | 该进 CLAUDE.md？ | 示例 |
|------|-----------------|------|
| **规则** | ✅ | 边界约定、禁止事项、命令速查、踩坑警示 |
| **便条** | ❌ | 历史叙事（"X 时刻起 Y 上线"）、详细机制、单次事故复盘 |

### 检查方法

```bash
# 查看文件行数
wc -l CLAUDE.md AGENTS.md

# 查看本次变更行数
git diff --stat HEAD~1 CLAUDE.md AGENTS.md
```

如果 `insertions` - `deletions` > 30，回头审查：
- 这条加的是"下次 AI 写代码时必须看到"的规则？→ ✅ 保留
- 这条是"上次会话告诉下次会话发生了什么"的便条？→ ❌ 删除或迁移到 docs/

---

## 编辑原则

### 1. 减优于加（最重要）

能删的先删，不能删的迁去 docs，最后剩下的才是规则。

**常见删除场景**：
- 完成的临时计划 → 删
- 推翻的决策 → 删
- 已被新版本取代的"中间态"叙事（"5/6 改了 X，5/8 又改成 Y"）→ 只留最终态
- 单次事故的流水账复盘 → 提炼成 1 行红线规则，事故详情归 docs/issues/ 或删

### 2. 合并优于追加

新信息是对旧信息的更新，改旧条目；新加条目前先 grep 同关键字，看现有条目能不能并。

```bash
# 添加新规则前先搜索
grep -i "关键词" CLAUDE.md
```

### 3. 删除优于保留

**判断标准**：这条信息在下次 AI 写代码时如果没看到，会不会犯错？

不会犯错 → 删除或迁移到 docs/

### 4. 指针不重复

同一条事实如果 docs/ 里已详写，CLAUDE.md 只在「深入文档」指针表里出现一次，不在概览段再叙事一次。

**反模式**：
```markdown
## 项目概述
系统新增了 device flow 五个路由，详见 docs/architecture.md §5。

## 深入文档
- architecture.md — 架构、数据流、device flow
```

**正确做法**：
```markdown
## 项目概述
（项目一句话定位，不提具体路由）

## 深入文档
- architecture.md — 架构、数据流、device flow
```

## 反膨胀检查清单

每次更新 CLAUDE.md/AGENTS.md 后，逐项检查：

### 尺寸检查
- [ ] 净涨幅 ≤ 30 行
- [ ] 总行数 < 500 行
- [ ] 没新增 "X 起 Y 上线，详见 docs/" 这种 blockquote 历史叙事
- [ ] 没在 CLAUDE.md 抄 docs/ 已有的详细机制

### 内容检查
- [ ] 每条新增内容都通过"下次 AI 不看会犯错吗"测试
- [ ] 同一事实没在多个位置重复
- [ ] 指针表已包含所有详细机制的文档引用

### 迁移检查
- [ ] 详细机制说明已迁移到 docs/design/ 或 docs/architecture/
- [ ] 历史叙事已迁移到 CHANGELOG 或删除
- [ ] 单次事故复盘已迁移到 docs/issues/ 或删除

---

## 精简策略

当文件超尺寸时，按以下顺序精简：

### 第一轮：删除明显冗余
1. 扫描顶部 blockquote / 历史叙事段 → 删除或迁移到 docs/
2. 项目概览只留 1-3 行 + 关键速查表
3. 删除"提醒下次会话"的便条（应该在 memory 里，不在 CLAUDE.md）

### 第二轮：合并重复
1. Grep 查找重复关键词
2. 合并说同一件事的多个条目
3. 删除已被取代的旧版本规则

### 第三轮：提取到 docs/
1. 详细机制 → docs/design/ 或 docs/architecture/
2. 使用示例 → docs/prd/ 或 docs/handover/
3. 运维手册 → docs/handover/

### 第四轮：提取到指针表
1. 将详细内容移到 docs/
2. 在 CLAUDE.md 的「深入文档」指针表里添加一行
3. 删除 CLAUDE.md 中的详细内容

## 反模式示例

### 反模式 1：历史叙事

```markdown
❌ 错误：
> 2026-05-08 timelineAt 功能上线，支持精确时间戳查询。
> 详见 docs/architecture.md §5.4

✅ 正确：
（在「深入文档」指针表里）
- architecture.md §5.4 — timelineAt 功能、时间戳查询
```

### 反模式 2：详细机制抄写

```markdown
❌ 错误：
## 评分算法
用户评分 = (点赞数 * 2 + 收藏数 * 3) / (发布天数 + 1)
衰减系数 = 0.95^天数
最终得分 = 用户评分 * 衰减系数

✅ 正确：
## 评分算法
见 docs/design/scoring.md（包含公式、参数、调优历史）
```

### 反模式 3：单次事故复盘

```markdown
❌ 错误：
> 2026-04-30 服务挂了 30min，原因是裸跑 `systemctl stop aihot-worker`
> 导致任务队列堆积，详见 docs/issues/2026-04-30-outage.md

✅ 正确：
## 红线规则
- 禁止裸跑 `systemctl stop aihot-worker`（会导致任务队列堆积）
```

---

## 执行顺序

**先精简（破除膨胀）→ 再做本次会话增量同步（补漏）**

两件事不能合并：
- 精简时心态是"什么不该在这"
- 补漏时心态是"什么该补到这"

混着做会两头不到位。
