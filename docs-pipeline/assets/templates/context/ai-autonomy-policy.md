# AI Autonomy Policy / AI 自主级别政策

> 定义 AI 在不同情况下的自主级别和受保护区域。

## 自主级别

| 级别 | 名称 | 说明 | 适用场景 |
|------|------|------|---------|
| `implement` | 执行 | AI 可以直接执行，不需要停下来问 | 低风险、本地修改、已有明确 owner doc |
| `plan-first` | 计划优先 | 先出计划，等确认再执行 | 中等复杂度、涉及多个模块 |
| `ask-first` | 先问 | 执行前必须确认 | 高风险变更、受保护区域 |
| `blocked` | 阻止 | 不能执行，必须人工介入 | 最高风险区域 |
| `research-only` | 仅研究 | 只研究和报告，不执行 | 探索阶段、不确定是否该做 |

## 受保护区域

> 这些区域是高风险变更区域，AI 必须先问才能操作。

| 区域 | 风险类型 | 自主级别要求 |
|------|---------|--------------|
| `<区域1>` | 认证/权限/支付/数据删除 | `ask-first` |
| `<区域2>` | 数据库 Schema 变更 | `ask-first` |
| `<区域3>` | 公共 API 契约 | `ask-first` |
| `<区域4>` | 部署配置 | `ask-first` |
| `<区域5>` | 外部集成 | `ask-first` |

## 默认自主级别

对于未列出的区域，默认自主级别为：

- **低风险本地修改**：直接执行，不问
- **中等复杂度变更**：先出计划
- **高风险变更**：先问

## 判定规则

根据任务特征确定自主级别：

### implement（直接执行）

满足以下**全部**条件：
- 单文件修改
- 变更少于 50 行
- 无 API/数据结构变化
- 无外部依赖变更
- 有明确的实现方案

**示例**：修复拼写错误、调整样式、添加日志、补充单元测试

### plan-first（计划优先）

满足以下**任一**条件：
- 多文件修改（≥2 个文件）
- 重构或迁移类任务
- 测试策略变化
- 涉及业务逻辑变更
- 预计变更超过 200 行

**示例**：重构函数、添加新功能、优化性能、重构测试

### ask-first（先问再做）

满足以下**任一**条件：
- 删除数据或文件
- 改变公开 API 契约
- 引入新的外部依赖
- 影响安全边界
- 修改认证/权限逻辑
- 数据库 Schema 变更
- 部署配置变更

**示例**：删除用户数据、修改 API 响应格式、添加新依赖、修改登录逻辑

### blocked（阻止执行）

满足以下**任一**条件：
- 缺少必要的凭据或权限
- 无法复现问题
- 需求互相冲突
- 需要外部审批
- 涉及法律/合规问题

**示证**：需要生产环境权限、需求文档矛盾、需要法务审批

### research-only（仅研究）

满足以下**全部**条件：
- 问题定义不清晰
- 解决方案不确定
- 需要技术调研
- 可能涉及多个方案对比

**示例**：技术选型、可行性分析、性能瓶颈定位
