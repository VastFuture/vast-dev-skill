# 讨论写作指南

## 用途

用 `docs/discussions/` 捕获模糊工作的多轮澄清。

## 适用场景

- PM 只能做部分确认
- 原型含义不明确
- 存在多种合理的需求解读
- 开发者需要从原始文件推断领域规则

## 包含内容

- 被讨论的源文件
- 开放问题
- 候选解读
- 已确认的决策
- 阻塞实现的未解决项

## 规则

讨论文件用于澄清，不是最终真相。将已确定的结论移入 `docs/prd/`、`docs/design/` 或 `ARCHITECTURE.md`。

## 文件名指引

偏好带日期的文件名：

- `docs/discussions/YYYY-MM-DD-主题.md`
