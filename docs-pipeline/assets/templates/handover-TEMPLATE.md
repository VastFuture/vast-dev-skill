## 项目概述

**项目名称**：电商后台管理系统

**项目目标**：为电商平台提供完整的后台管理功能，包括商品管理、订单处理、用户管理和数据分析

**技术栈**：
- 后端：Spring Boot 2.7.0 + MyBatis Plus
- 前端：React 18 + Ant Design 5.0
- 数据库：MySQL 8.0 + Redis 7.0
- 部署：Docker + Kubernetes

**项目状态**：
- 开发进度：85%
- 测试进度：70%
- 上线状态：已上线核心功能，高级功能开发中

## 技术架构

### 系统架构图

```
[前端React] -> [网关] -> [后端服务集群]
                           ├── 商品服务
                           ├── 订单服务  
                           ├── 用户服务
                           └── 统计服务
                              ↓
                         [MySQL主从] + [Redis缓存]
```

### 核心模块

| 模块 | 职责 | 关键文件 | 负责人 |
|------|------|----------|--------|
| 商品管理 | 商品CRUD、库存管理、分类管理 | ProductController.java | 王五 |
| 订单管理 | 订单处理、状态流转、支付对接 | OrderService.java | 赵六 |
| 用户管理 | 用户信息、权限控制、角色管理 | UserController.java | 钱七 |
| 数据统计 | 销售报表、用户分析、实时监控 | StatisticsService.java | 孙八 |

### 数据模型

核心实体：用户(User)、商品(Product)、订单(Order)、订单项(OrderItem)
关联关系：用户-订单(1:N)、订单-订单项(1:N)、商品-订单项(1:N)

### API 接口

核心API接口：
- /api/products - 商品管理接口
- /api/orders - 订单管理接口  
- /api/users - 用户管理接口
- /api/statistics - 数据统计接口

## 关键决策记录

### 决策 1：使用 Redis 做订单缓存而非 MongoDB

**日期**：2026-04-15

**背景**：订单查询QPS较高，需要引入缓存层提升性能

**决策**：选择 Redis 作为订单缓存，而不是 MongoDB

**理由**：Redis 内存操作速度更快，团队熟悉度高，运维成本低

**影响**：订单查询性能提升80%，但需要处理缓存一致性问题

### 决策 2：订单状态使用状态机模式

**日期**：2026-05-10

**背景**：订单状态流转复杂，容易出现状态不一致问题

**决策**：引入状态机模式管理订单状态流转

**理由**：保证状态流转的安全性和一致性，便于扩展新状态

**影响**：订单状态管理更加规范，但增加了代码复杂度

## 已知问题

### 问题 1：高峰期订单查询响应慢

**严重程度**：🟡 中等

**描述**：在订单量大于10000时，订单列表查询响应时间超过3秒

**影响范围**：订单管理模块的列表查询功能

**临时解决方案**：增加 Redis 缓存有效期，减少数据库查询

**根本解决方案**：在 order 表的 create_time 和 status 字段上添加联合索引

### 问题 2：库存扣减并发安全问题

**严重程度**：🔴 严重

**描述**：高并发下可能出现库存超卖现象

**影响范围**：商品下单流程

**临时解决方案**：使用 Redis 分布式锁控制库存扣减

**根本解决方案**：重构为基于消息队列的异步库存扣减机制

## 开发环境

### 环境配置

```bash
# 克隆项目
git clone https://github.com/company/ecommerce-admin.git

# 安装依赖
cd ecommerce-admin
npm install
mvn dependency:resolve

# 配置环境变量
cp .env.example .env
# 编辑 .env 文件配置数据库连接

# 启动开发服务器
# 后端
mvn spring-boot:run
# 前端
npm run dev
```

## 部署流程

### 部署环境

| 环境 | 地址 | 用途 |
|------|------|------|
| 开发环境 | http://dev.admin.company.com | 开发测试 |
| 测试环境 | http://test.admin.company.com | 功能测试 |
| 生产环境 | http://admin.company.com | 正式环境 |

### 部署步骤

1. 构建 Docker 镜像：`docker build -t ecommerce-admin:v1.0.0 .`
2. 推送到镜像仓库：`docker push registry.company.com/ecommerce-admin:v1.0.0`
3. 在 K8s 集群中更新部署：`kubectl set image deployment/ecommerce-admin app=registry.company.com/ecommerce-admin:v1.0.0`

### 回滚流程

1. 查看历史版本：`kubectl rollout history deployment/ecommerce-admin`
2. 回滚到上一版本：`kubectl rollout undo deployment/ecommerce-admin`
3. 检查回滚状态：`kubectl rollout status deployment/ecommerce-admin`
