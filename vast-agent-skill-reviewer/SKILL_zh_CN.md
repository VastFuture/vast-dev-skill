# Agent Skill Reviewer

## 使用说明

当用户要求审查 Agent Skill 时，请按照以下步骤确保该技能符合最佳实践。

### 1. 确定目标

确定待审查 Agent Skill 的目录路径。读取目录结构和 `SKILL.md` 文件内容。

### 2. 分析目录结构

检查项目是否符合生产级目录结构规范：

- **目录名称**：必须使用 `kebab-case` 命名。
- **核心文件**：确保核心指令文件命名为 `SKILL.md`（大写）。
- **关注点分离**：检查是否有合适的子目录（例如，`scripts/` 存放可执行代码，`references/` 存放文档，`assets/` 存放静态文件）。

### 3. 审查命名规范

- **角色命名**：检查技能名称是否使用 **名词/执行者** 格式，而非动词/动作格式（例如，应使用 `agent-skill-reviewer` 而非 `agent-skill-review`）。

### 4. 审查 Frontmatter（元数据层）

- 读取 `SKILL.md` 的 YAML frontmatter。
- **Name**：验证 `name` 字段存在且与目录名一致。
- **Description 公式**：验证 `description` 遵循黄金公式：`[功能] + [触发场景] + [关键词]`。描述必须足够具体，使 LLM 能够判断何时触发该技能。

### 5. 审查 Instructions（核心逻辑层）

- **清晰度**：检查指令是否清晰、分步骤，便于 LLM 遵循。
- **状态与并发**：确保技能不在单个对话线程内尝试处理高度并行的并发任务，因为技能会修改上下文状态。
- **逻辑外置**：如果复杂逻辑可以外置到外部工具或脚本（例如 `scripts/` 中），则不应硬编码在 Markdown 中。
- **渐进式披露**：验证详细的补充知识放置在 `references/` 中，而非堆砌在主 `SKILL.md` 中。

### 6. 报告审查结果

使用以下格式向用户呈现结构化审查报告：

- **目录结构与命名**：通过/不通过，附详细说明。
- **Frontmatter**：通过/不通过，附详细说明。
- **Instructions**：通过/不通过，附详细说明。
- **改进建议**：针对任何违反最佳实践的行为，提供可操作的改进建议。
