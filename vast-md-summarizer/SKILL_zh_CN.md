# Markdown Summarizer

分析和总结本地 Markdown 文件的文本内容，输出结构化的中文分析结果。

## 工作流程

### 步骤一：读取并验证内容

使用相应的文件读取工具读取用户指定的本地 Markdown 文件内容。如有多个文件，尽可能并行读取。
**验证**：读取后验证内容完整性。若文件完全为空或缺乏实质性文本内容（例如仅含少量图片链接），立即通知用户并中止该文件的摘要生成。

### 步骤二：分析内容

对每个文件，按以下章节输出结构化的中文分析。输出内容须专业、客观且有深度。

```markdown
## [文件名]

### 1. 核心概要

概述文档的核心信息和主题的一段话总结。

### 2. 关键要点

- 使用无序列表突出最重要的要点、事实或论点。保持简洁。

### 3. 深度解析

深入探讨内容的重要性、背景和细节。

- 重点说明文中的底层逻辑或机制。
- 包含文中的关键数据、统计或证据。
- 指出作者的主要立场或倾向（如适用）。

### 4. 值得关注的细节

文档中值得注意的引用、独特视角、出人意料的信息或边缘案例。

### 5. 结论与行动建议

从内容中得出的可执行建议、推荐或后续步骤。
如不适用，则总结最终结论。
```

### 步骤三：多文件对比分析（当提供多个文件时）

在逐一分析完每个文件后，添加一个综合对比章节：

```markdown
## 综合对比分析

### 共同主题

识别所有文档中的共同概念、一致观点或行业趋势。

### 差异与冲突

重点指出各来源之间冲突的数据、不同的观点或不同的方法论。

### 综合结论

将所有提供文档的洞察合并为一个统一的结论。
```

## 规则

- **输出语言**：无论源语言是什么，最终分析始终以中文输出。
- **准确性**：保持事实准确性，不得虚构或捏造源文本中不存在的信息。
- **格式规范**：确保中英文字符之间以空格分隔。
- **长内容处理**：对于内容过长导致截断的文档，聚焦于已获取的最实质内容，并添加免责声明："_注意：原文内容过长，以下分析基于已获取的部分核心内容。_"
- **自适应输出**：
  - 若用户提供了文件但未给出明确指示，默认输出完整的结构化分析。
  - 若用户明确要求"简单总结"，则仅输出"核心概要"和"关键要点"两个章节。
