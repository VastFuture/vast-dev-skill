# /wiki-query — 查询知识库

从 LLM Wiki 知识库中查询信息。先定位后深入，有价值的答案自动归档。

## 查询流程

### 步骤 0：读取配置

在执行查询前，先确定知识库路径：

1. 读取配置文件：
   - **优先项目模式**：检查当前目录是否存在 `wiki-config.json`（`scope: "project"`）
   - **全局模式**：`~/.config/opencode/wiki-config.json`（`scope: "global"`）
2. 从配置中获取 `kbPath`（知识库根目录）
3. 若配置不存在或 `kbPath` 为空，提示用户先执行 `/wiki-init` 初始化知识库
4. `wiki/` 目录即 `{kbPath}/wiki/`，`raw/` 即配置中的 `rawPath`

### 步骤 1：先读目录

读取 `{kbPath}/wiki/index.md`，定位与问题相关的页面

### 步骤 2：深入阅读

逐个阅读 `{kbPath}/wiki/` 下的相关页面，理解上下文

### 步骤 3：综合答案

跨页面综合信息，形成完整答案，附引用

### 步骤 4：归档判断

判断答案是否值得长期保留，值得则归档到 `{kbPath}/wiki/综合/`

## 归档规则

以下情况应将答案归档为新的 wiki 页面：
- 比较分析（如：A 和 B 的优缺点对比）
- 新发现的跨页面关联
- 需要反复查阅的综合答案
- 深度研究报告

**归档目录**：`wiki/综合/`

**文件命名**：保持 wikilink 兼容，以问题主题命名

## 不归档的情况

- 简单的事实性回答
- 不需要复用的临时问题
- 可以从现有页面直接得到的答案

## 输出要求

- 使用简体中文
- 附带来源引用（页面路径 + 章节）
- 多页面综合时注明跨页面关联

## 工具使用规则

**更新 index.md、log.md 等累积性文件时**：
- 必须先用 `Read` 读取当前内容
- 必须用 `Edit` 工具做增量修改（追加、替换）
- 禁止用 `Write` 工具覆盖整个文件

**Write 工具仅用于**：
- 创建全新文件
- 用户明确要求覆盖整个文件

## 脚本执行优先级

需要执行脚本操作时，按以下顺序选择实现方式：

1. **Python** — 检测到 Python 环境则优先使用
2. **Linux** — Shell 脚本（bash/sh）
3. **Windows + Git Bash** — 用 Git Bash 执行
4. **Windows（无 Git Bash）** — PowerShell
