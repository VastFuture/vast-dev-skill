# Content Rewriter

IRON LAW: 改写必须保持核心信息和事实完整,只改变表达方式。禁止通过简单的同义词替换来"凑"相似度,必须真正理解内容后用自己的方式重新表达。

## Workflow

Copy this checklist and check off items as you complete them:

```
Content Rewriter Progress:

- [ ] Step 1: 分析原文与确定改写目标 ⚠️ REQUIRED

  - [ ] 1.2 确认改写场景与目标受众
  - [ ] 1.3 确认改写风格与要求
- [ ] Step 2: 加载改写策略 ⛔ BLOCKING
  - [ ] 2.1 根据场景选择策略
  - [ ] 2.2 加载对应的参考规则
- [ ] Step 3: 执行改写
  - [ ] 3.1 深度理解原文语义
  - [ ] 3.2 重新组织结构与逻辑
  - [ ] 3.3 用目标风格重新表达
- [ ] Step 4: 质量检查 ⚠️ REQUIRED
  - [ ] 4.1 核对核心信息是否完整
  - [ ] 4.2 检查相似度是否合理(40-60%)

```

## Step 1: 分析原文与确定改写目标 ⚠️ REQUIRED

### 1.1 理解原文核心信息

Ask yourself:
- 这篇内容的核心观点/信息是什么?
- 哪些是事实,哪些是观点?
- 哪些信息是必须保留的?
- 原文的逻辑结构是什么?

**不要**只是浏览原文,必须**深度理解**才能真正改写。

### 1.2 确认改写场景与目标受众

Ask user (if not clear):
- 改写后的内容用于什么场景?
  - 多平台适配? (微信/知乎/小红书/抖音/B站)
  - 受众转换? (专业→科普 / 正式→口语)
  - 营销需求? (生成多个角度的文案)
  - 其他?

- 目标受众是谁?
  - 专业人士 / 普通大众 / 学生 / 特定行业人群?

### 1.3 确认改写风格与要求

Ask user (if not specified):
- 期望的风格是?
  - 语气: 正式/口语化/幽默/严肃/热情/冷静
  - 详细程度: 简化/详细/保持
  - 专业度: 专业术语/通俗表达/科普化
  
- 特殊要求?
  - 字数要求?
  - 必须包含/避免的元素?
  - 相似度要求? (默认40-60%)

## Step 2: 加载改写策略 ⛔ BLOCKING

根据用户的场景选择合适的策略:

### 场景A: 多平台适配
→ Load references/platform-styles.md

包含:
- 微信公众号: 专业权威、结构清晰、适度正式
- 知乎: 深度分析、逻辑严密、引用数据
- 小红书: 轻松种草、多用emoji、突出体验
- 抖音/B站: 口语化、节奏感强、引发互动

### 场景B: 受众转换
→ Load references/audience-transformation.md

包含:
- 专业→科普: 去术语、加比喻、分步骤
- 正式→口语: 简化句式、加语气词、用第一人称
- 通用→特定行业: 增加行业术语、调整关注点

### 场景C: 文风调整
→ Load references/tone-styles.md

包含:
- 严肃→幽默: 加自嘲、用梗、夸张手法
- 冷静→热情: 情感词汇、感叹句、号召性语言
- 客观→主观: 个人体验、情感表达、价值判断

### 场景D: 营销文案变体
→ Load references/marketing-angles.md

包含:
- 性能角度、价格角度、用户体验角度
- 社会认同角度、技术创新角度、情感共鸣角度

## Step 3: 执行改写

### 3.1 深度理解原文语义

不要急于开始改写,先完成以下理解:
1. 提取核心观点(1-3句话概括)
2. 识别论据和例证
3. 理解逻辑关系
4. 把握情感基调

### 3.2 重新组织结构与逻辑

Ask yourself:
- 目标风格下,什么样的结构更合适?
- 是否需要调整段落顺序?
- 是否需要增删内容模块?

**允许的调整**:
- 改变段落顺序
- 合并或拆分段落
- 调整详略分配
- 增加过渡句

**不允许的调整**:
- 删除核心论点
- 添加原文没有的事实
- 改变因果关系

### 3.3 用目标风格重新表达

**改写技巧** (从高到低的质量):

**优先使用** (高质量改写):
1. **改变句式结构**: 主动→被动、陈述→疑问、长句→短句
2. **换角度表达**: 从不同视角重述同一事实
3. **改变修辞手法**: 比喻→类比、排比→递进
4. **调整详略**: 某部分详细展开,另一部分精简概括

**谨慎使用** (中等质量):
5. **同义替换**: 仅在必要时使用,不要生硬替换
6. **增删例证**: 用不同的例子说明同一观点

**禁止使用** (低质量):
7. ❌ 简单的同义词批量替换
8. ❌ 只改连接词和语气词
9. ❌ 打乱顺序但句子不变

## Step 4: 质量检查 ⚠️ REQUIRED

### 4.1 核对核心信息是否完整

逐条检查:
- [ ] 原文的核心观点都保留了吗?
- [ ] 关键数据和事实是否准确?
- [ ] 逻辑关系是否保持?
- [ ] 有没有添加原文没有的信息?

### 4.2 检查相似度是否合理

**目标相似度**: 40-60%

**判断标准**:
- **相似度过高 (>70%)**: 改写不充分,过于接近原文
- **相似度过低 (<30%)**: 可能偏离原意,核心信息丢失
- **相似度合理 (40-60%)**: 既保持信息完整,又充分改写

**如何调整**:
- 相似度过高 → 尝试更多的句式变换和结构调整
- 相似度过低 → 检查是否遗漏了重要信息

### 4.3 验证目标风格是否达成

Ask yourself:
- 改写后的内容符合目标平台/受众的习惯吗?
- 语气和风格是否统一?
- 是否达到了用户指定的要求?

## Step 5: 输出结果

### 5.1 提供改写后的内容

**输出格式** (默认):
```
## 改写后内容

[改写后的完整内容]

---

### 改写说明
- 目标场景: [平台/受众]
- 风格调整: [主要风格变化]
- 字数: 原文 XXX 字 → 改写后 XXX 字
```

### 5.2 说明主要改动点 (可选)

如果用户要求查看改动细节,提供:
- 结构调整: 说明段落顺序、详略的主要变化
- 表达变化: 列举几个典型的改写示例
- 风格特征: 指出目标风格的体现之处

## Anti-Patterns

Do NOT:
- ❌ 使用简单的同义词批量替换工具思维
- ❌ 只改连接词、语气词就算"改写"
- ❌ 为了凑相似度而生硬改词
- ❌ 添加原文没有的事实或观点
- ❌ 删除重要的核心信息
- ❌ 改变因果关系或逻辑结构
- ❌ 把正确的专有名词"改写"成错误的
- ❌ 不理解原文就开始机械改写
- ❌ 所有句子都用同一种改写套路

## Common Edge Cases

### 例外1: 专有名词不改写
```
保持原样:
- 人名: 张三、Steve Jobs
- 地名: 北京、Silicon Valley
- 产品名: iPhone、微信
- 技术术语: API、机器学习
```

### 例外2: 数据和引用保持准确
```
必须精确:
- 统计数据: "增长了50%" 不能改成"大约一半"
- 时间: "2023年" 不能改成"近年来"(除非明确要求模糊化)
- 引用: 如果引用了某人的话,必须保持引用的准确性
```

### 例外3: 多版本生成
如果用户要求生成多个版本:
```
- 明确每个版本的差异点(角度/风格/受众)
- 确保版本之间有明显区分度
- 每个版本都完成完整的质量检查
```

### 例外4: 极短文本
对于很短的文本(< 100字):
```
- 改写难度大,相似度可能偏高,这是正常的
- 重点放在句式和表达方式的变化上
- 告知用户短文本改写的局限性
```

## Pre-Delivery Checklist

### 内容完整性
- [ ] 所有核心观点都保留
- [ ] 关键数据准确无误
- [ ] 逻辑关系清晰
- [ ] 没有添加虚假信息

### 改写质量
- [ ] 相似度在合理范围(40-60%)
- [ ] 不是简单的同义词替换
- [ ] 句式结构有明显变化
- [ ] 段落组织合理

### 风格达成
- [ ] 符合目标平台/受众的风格
- [ ] 语气统一
- [ ] 用户特殊要求已满足

### 输出规范
- [ ] 格式清晰易读
- [ ] 字数符合要求(如有)
- [ ] 提供了必要的说明信息
