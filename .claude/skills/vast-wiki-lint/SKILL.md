# /wiki-lint — 健康巡检

定期检查 LLM Wiki 知识库的健康状况，输出报告。

定期检查 LLM Wiki 知识库的健康状况，输出报告。

## 执行前置步骤

### 步骤 0：读取配置

1. 读取配置文件：
   - **优先项目模式**：检查当前目录是否存在 `wiki-config.json`（`scope: "project"`）
   - **全局模式**：`~/.config/opencode/wiki-config.json`（`scope: "global"`）
2. 从配置中获取 `kbPath`（知识库根目录）
3. 若配置不存在或 `kbPath` 为空，提示用户先执行 `/wiki-init` 初始化知识库
4. `wiki/` 目录即 `{kbPath}/wiki/`，`raw/` 即配置中的 `rawPath`

### 步骤 1：自动分类（classify）

1. 使用 Skill 工具加载 `wiki-classify` skill
2. 完整执行其定义的分类流程
3. classify 完成后继续巡检流程

## 扫描范围

- **wiki/**：`{kbPath}/wiki/` 下全部 `.md` 文件和 `.canvas` 文件
- **raw/**：`{rawPath}` 下全部子目录中的 `.md` 文件（含 `raw/Clippings/` 等）
- **排除**：`assets/`（仅图片资源，无需扫描）

## 检查项目

### 1. 页面矛盾
- 搜索 wiki 中互相矛盾的断言
- 标注矛盾位置和建议修正方向

### 2. 过时主张
- 检查被新资料取代的旧主张
- 标注需要更新的页面

### 3. 孤立页面
- 搜索无入链的页面（无其他页面引用）
- 建议添加交叉引用或合并

### 4. 缺失页面
- 被提及但缺乏独立页面的重要概念
- 建议创建新页面

### 5. 缺失交叉引用
- 相关内容未建立 wikilink 链接
- 建议添加关联

### 6. 数据空白
- 可通过网络搜索填补的知识空白
- 建议搜索方向和关键词

### 7. Raw 覆盖率
- 检查 `{rawPath}` 所有子目录中的 `.md` 文件是否都有对应的 `{kbPath}/wiki/摘要/` 页面
- 列出未摄入的 raw 文件
- 排除 `assets/` 目录

## 输出格式

```markdown
## 巡检报告 — 2026-04-30

### 矛盾（N 项）
- [页面A] 与 [页面B] 在 [主题] 上矛盾...

### 过时（N 项）
- [页面] 中的 [主张] 已被 [新资料] 取代...

### 孤立页面（N 项）
- [页面] — 无入链，建议...

### 建议（N 项）
- ...
```

## 工具使用规则

**更新 index.md、log.md 等累积性文件时**：
- 必须先用 `Read` 读取当前内容
- 必须用 `Edit` 工具做增量修改（追加、替换）
- 禁止用 `Write` 工具覆盖整个文件

**Write 工具仅用于**：
- 创建全新文件
- 用户明确要求覆盖整个文件

## 脚本执行优先级

需要执行脚本操作时，按以下顺序选择实现方式：

1. **Python** — 检测到 Python 环境则优先使用
2. **Linux** — Shell 脚本（bash/sh）
3. **Windows + Git Bash** — 用 Git Bash 执行
4. **Windows（无 Git Bash）** — PowerShell
