# backlog/ 目录说明

## 职责

存放项目的需求池和待办事项，包括：
- 功能需求
- 技术改进
- 文档更新
- Bug 修复

## 文件组织

建议按优先级或模块组织：

```
backlog/
├── P0-critical/     # 紧急修复
├── P1-high/         # 高优先级
├── P2-medium/       # 中优先级
├── P3-low/          # 低优先级
└── backlog.md       # 汇总看板
```

## 使用场景

- 需求评审时，从 backlog 中筛选需求
- 迭代规划时，确定当前迭代要做的需求
- 日常开发时，记录发现的问题和改进点

## 维护规则

1. 新需求先进入 backlog，评审后再进入 features/
2. 保持每个条目的可执行性
3. 定期清理过时条目
